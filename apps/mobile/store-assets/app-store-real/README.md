# app-store-real — captured JUNO screenshots (regenerate before submission)

This directory is for App Store screenshots **composed from real JUNO
screen captures** (`scripts/compose-app-store-screenshots-from-captures.mjs`).

It is intentionally **empty**. The previous contents were removed on
2026-05-22 because they were not submittable:

- `01-discover-real-profiles.png`, `02-chat-real-context.png`,
  `03-synastry-score.png`, `04-cosmic-premium-tools.png`,
  `05-celestial-insights.png` — pre-rebrand captures that show the old
  **AstroDating** wordmark in the header.
- `01-synastry-insight.png` … `05-relationship-dynamics.png` — JUNO-framed
  composites, but the embedded phone capture still showed the old
  AstroDating UI (the source captures in
  `apps/web/public/screenshots/` predate the JUNO rebrand).

A screenshot that shows `AstroDating` anywhere — including inside the
framed phone — must never be uploaded to App Store Connect.

## Two ways to produce the store screenshots

### A. Synthetic placeholders — ready now

`apps/mobile/store-assets/app-store/` already holds 5 fully synthetic,
JUNO-branded shots (iPhone 6.9" + iPad 13") generated by
`node scripts/generate-app-store-screenshots.mjs`. They carry no
AstroDating brand, no swipe deck, no like/pass and no match-celebration,
and follow the narrative in `docs/marketing/screenshot-seed-notes.md`.
They are submittable as-is.

### B. Real captures — regenerate this directory

To compose real screenshots into this directory:

1. Recapture the source screens from a **JUNO-branded** build (the web
   app once redeployed, or the mobile app) into
   `apps/web/public/screenshots/` — `discover.png`, `chat.png`,
   `compatibility.png`, `premium-cosmic.png`, `premium-celestial.png`.
   Follow `docs/marketing/screenshot-seed-notes.md` (Phase 3).
2. Confirm none of the captures show the `AstroDating` wordmark.
3. Run `node scripts/compose-app-store-screenshots-from-captures.mjs`.
4. The 5 framed shots land back in `app-store-real/iphone-6-9/`.

Until step 1 is done against a JUNO build, submit the synthetic set from
`app-store/` instead.
